Replit AI Prompt — “Fix Smart Assignee + Invite (mount router, schema, client types)”

We’re in a Vite + React + Tailwind + shadcn client and an Express + TypeScript + Drizzle backend.

1) Mount the users router (the missing piece)

Edit server/routes.ts (or your server entry that registers routes):
	•	Add at the top:

import usersRouter from "./users"; // path is correct: file is /server/users.ts

	•	In registerRoutes(app) before other catch-alls/static handlers, add:

app.use("/api/users", usersRouter);

This enables GET /api/users/search, POST /api/users/invite, and POST /api/users/invite/accept that already exist in users.ts.

2) Allow pending invite on insert (schema)

Edit shared/schema.ts:
	•	Keep the tasks column (already present):

pendingAssigneeInviteId: integer("pending_assignee_invite_id"),

	•	Extend the insert schema to include the field (currently missing):

export const insertTaskSchema = createInsertSchema(tasks)
  .omit({ id: true, createdAt: true, updatedAt: true })
  .extend({
    status: z.enum(['pending','in-progress','review','completed','blocked']).default('pending'),
    assigneeEmail: z.string().email().optional(),
    pendingAssigneeInviteId: z.number().int().optional().nullable(), // <-- add this
  });

If you validate with this schema before insert, the field will now pass through and persist.

3) Make sure user IDs stay strings end-to-end

Server (users.ts): in the /search response, keep id as a string (do not parseInt). If any conversion to numbers exists, remove it.

Client (AssigneeSmartInput.tsx):

type FoundUser = { id: string; email: string; name?: string; avatarUrl?: string | null };

type Resolve =
  | { type: "existing"; userId: string; email: string; name?: string }
  | { type: "invite"; inviteId: number; email: string };

When user chooses a match:

onResolve({ type: "existing", userId: user.id, email: user.email, name: user.name })

When user chooses “Invite ”:

const r = await fetch("/api/users/invite", { method:"POST", headers:{"Content-Type":"application/json"}, body: JSON.stringify({ email })});
if (r.status === 409) {
  // already exists → switch to existing
  const { userId } = await r.json();
  onResolve({ type: "existing", userId, email });
} else if (r.ok) {
  const { inviteId } = await r.json();
  onResolve({ type: "invite", inviteId, email });
}

Task form wiring (e.g., TaskWizard.tsx):

<AssigneeSmartInput
  onResolve={(r) => {
    if (r.type === "existing") {
      form.setValue("assigneeId", r.userId);      // string
      form.setValue("assigneeEmail", "");         // clear
      setAssigneeDisplay(r.name || r.email);
    } else {
      form.setValue("assigneeId", undefined as any);
      form.setValue("assigneeEmail", r.email);    // <-- only email
      setAssigneeDisplay(`${r.email} (invited)`);
      toast.success(`Invitation sent to ${r.email}.`);
    }
  }}
/>

Important: when inviting, do not also send an assigneeId. The server prefers assigneeId and will skip the invite flow.

	•	Even when the server created an invite, the task insert schema dropped pendingAssigneeInviteId, so auto-assignment could never complete later.
	•	A couple of places still treated user IDs as numbers, but your IDs are strings.
